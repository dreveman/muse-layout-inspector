# Install and update Layout Inspector (Muse assistant guide)

This guide is for **you, the user's Muse assistant**. On this platform the
app is a Hatch TypeScript web artifact; cloning the repository does not
install or publish that artifact by itself.

## 0. Confirm prerequisites and clone the repository

1. Confirm you have access to the web-artifact builder interface and its
   current **artifacts skill/instructions**. Those are authoritative for the
   exact plan → build → audit → submit procedure. Do not use `bun run build`,
   hand-edit `.space-build/`, or claim a local build deployed.
2. Clone (or update) the repository on the builder host:

   ```bash
   mkdir -p ~/workspace/github/dreveman
   git clone https://github.com/dreveman/muse-layout-inspector.git \
     ~/workspace/github/dreveman/muse-layout-inspector
   ```

   If the checkout already exists, run `git -C ~/workspace/github/dreveman/muse-layout-inspector pull --ff-only`.
   Never modify tracked files in the git checkout during installation.

## 1. Install or update the web artifact

The artifact's catalog slug is a **deploy-time variable** generated by the
platform when the artifact is created. The builder adopts source from
`~/workspace/ts-spaces/<slug>/` — the directory name, `space.json` slug, and
catalog slug must all match.

1. Check if a snapshot already exists at `~/workspace/ts-spaces/<slug>/` for
   Layout Inspector. If so, reuse that `<slug>` with the edit workflow after
   re-running `web/stage-snapshot.sh <slug>`.
2. If no snapshot exists (first install):
   a. Create a **fullstack TypeScript web Space** with display name
      `"Layout Inspector"` and a short `icon_subject` (e.g.
      `"A diagnostic ruler and viewport boundary inspector grid."`). Capture
      the generated `<slug>` from the create response.
   b. Stage the web-build snapshot and generate `space.json`:
      ```bash
      ~/workspace/github/dreveman/muse-layout-inspector/web/stage-snapshot.sh <generated-slug>
      ```
   c. Use the edit workflow with `<generated-slug>` to adopt the staged
      source.
3. Follow the current artifacts skill's **plan → build → audit → submit**
   flow, applying pending `drizzle/` migrations (`0000_init.sql`).
4. Once `submit` succeeds, report the live artifact slug and confirm that
   `getViewerInfo` and `listSnapshots` resolve cleanly.
